# 조은지 | 데이터분석에 관심 있는 개발 교육생

데이터분석에 관심 있는 개발 교육생 조은지입니다. AX 해커톤에서 구독관리 서비스의 챗봇 UI/UX를 설계하고 초기 데모 프로토타입과 서비스 캐릭터 Wonnie를 제작했습니다.

이 프로젝트에서 직접 맡은 화면 설계·구현과 캐릭터 제작 과정, 배운 점을 정리했습니다.

## 기술 사용 맥락

| 기술 | 프로젝트에서 사용한 방식 |
|---|---|
| Figma | 수정 가능한 화면 설계 |
| HTML·CSS·JavaScript | 데모 프로토타입 구현 |
| React | 화면 전환 구현 |

## 대표 프로젝트 — AX 해커톤 구독관리 챗봇

- **기간:** 10/26~10/28, 2박 3일
- **팀 규모:** 5명
- **대상 사용자:** 여러 구독서비스를 이용하며 구독내역을 한눈에 정리하고 싶은 사용자
- **내 역할:** 챗봇 UI/UX 설계, 데모 화면 구현, Wonnie 캐릭터 디자인

### 사용자 문제와 내가 구현한 데모 흐름

여러 구독서비스의 이용 현황을 한눈에 확인하고 개인별 일정/소비패턴에 맞는 구독 관리를 돕는 서비스를 기획했습니다.

데모에서는 다음 흐름을 표현했습니다.

1. 사용자가 챗봇에 구독 중인 서비스를 질문합니다.
2. 챗봇 화면에 구독현황을 표시합니다.
3. 구독 중인 서비스를 스와이프하면 다음 달 결제를 1회 잠그는 흐름을 보여줍니다.



## 개인 기여

### 챗봇 화면 설계와 구현

데모 시나리오를 바탕으로 화면 구성을 정하고 구현했습니다. Figma로 화면을 설계하고 HTML·CSS·JavaScript로 데모 프로토타입을 구현했습니다. 화면 전환에는 React를 사용했습니다.

제가 담당한 범위는 챗봇 화면 설계·데모 구현과 Wonnie 캐릭터 제작입니다.

### Wonnie 캐릭터 디자인

서비스 캐릭터 Wonnie와 상황별 표정을 디자인해, 화면·발표자료·영상에 활용할 수 있도록 팀에 제공했습니다.

## 어려움과 해결 과정

기획 초기에는 데모 시나리오가 명확하지 않아 구현 범위를 정하기 어려웠습니다. 화면 제작 후에도 시나리오가 추가되면서 수정 작업이 반복됐습니다.

이후 데모 시나리오가 확정된 뒤, 이를 기준으로 구현했습니다

소통 개선은 제가 체감한 변화이며, 별도로 측정하지는 않았습니다.

## 근거 자료와 확인 범위

| 자료 | 담고자 하는 내용 | 현재 확인 상태 |
|---|---|---|
| Figma | 화면 설계 결과 | 링크 제공. 설계 항목과 화면 배치를 확인함 |
| 데모 사이트 | 구현한 화면과 사용자 흐름 | 링크 제공. 이 초안 작성 과정에서는 실제 작동을 확인하지 못함 |
| Wonnie 첨부 이미지 | 캐릭터 디자인 결과 | 이미지 1장 확인 |
| 상황별 표정·적용 장면 | 캐릭터 제작 범위와 활용 | 본인 설명 기준. 표정 모음과 적용 자료는 추가 정리 필요 |

제가 구현한 데모에 대한 실사용자 검증과 성능 측정은 진행하지 않았습니다. 이 프로젝트에서 데이터 수집·정리·분석을 직접 수행했는지는 아직 확인되지 않아, 데이터분석 성과로 기재하지 않았습니다.

## 배운 점


- 짧은 일정일수록 데모 시나리오를 먼저 구체화하는 것이 구현 범위를 정하는 데 중요하다는 점을 배웠습니다.
- 프로토타입이 팀원 간 의사소통에 도움이 된다는 점을 경험했습니다.
